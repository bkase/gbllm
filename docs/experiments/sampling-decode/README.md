# Sampling decode bring-up (sampling_decode_bringup.v1)

Integer top-k/temperature sampling decode for the stateful arm-B checkpoint: the exp-LUT + XorShift16 design that the planv0 2026-07-04 amendment section 3 decode pin requires before `DecodeMode::TopKTemperature` can exist (F-G3, bd-a4du; this run is bead bd-2mjkd). Host semantics live in `gbf-kernel/src/decode.rs`; the ROM epilogue must reproduce them byte-exactly. Generated by `cargo run -p gbf-bench --bin sampling-decode`; every number below is program output at git `8dbb5b806725271913eedbb5921eb4fae8794515`.

## Pinned design

- RNG: XorShift16 (planv0 RngSpec::XorShift16), shift triple (7,9,8), full period 65535, seed 0 canonicalized to 1, one draw per token
- Exp LUT: 256 x u8, lut[u] = round_ties_even(255 * 2^(-u/16)); zero for u >= 144 (sha256 `ea328cd5a436b04e`)
- LUT index: u = min(255, (d * scale_q16 + 0x8000) >> 16), d = max_logit - logit in raw i24 logit units (round-half-up Q16 multiply)
- Selection: top-k by k partial scans; pass 0 is the deployed argmax rule; later passes skip used ids; ties go to the lower id
- Draw: threshold = (r * total_weight) >> 16 (truncating); pick the first candidate in selection order whose cumulative weight strictly exceeds it
- Temperature: scale_q16 = round_ties_even(65536 * 16 * logit_step / (T * ln 2)) folded at build time (logit step 6.321286e-3)

## Cycle cost of the sampling epilogue

- Argmax decode (same session, 256 tokens): **3532363 M-cycles/token**
- Sampling decode: **3581482 M-cycles/token** (+49119 M-cycles/token, +1.3905% — the forward pass dominates; the sampler adds k logit scans, one LUT multiply per candidate, one RNG step, and the cumulative walk)

## Caveats

- The output ring caps on-device runs at 256 tokens, so 512-char samples are host-generated; the ROM-verified sample's first 256 ids are byte-identical to an on-device run with the same (seed, rng_seed), and tokens 257..512 come from the same host evaluator that produced those verified ids.
- The scaled-multiply draw makes each candidate's probability deviate from weight/total by at most total/65536 (~3% relative at total ~2040); this is deterministic and identical on host and device.
- Successive XorShift16 values are a fixed permutation of 1..=65535, not independent draws; adequate for qualitative decoding variety, not for statistical workloads.
- Sample quality must be judged honestly: sampling escapes greedy argmax loops, but the model itself is a 4-block d64 bring-up checkpoint (~3.3 bpc), so text is English-like at best, not coherent prose.
