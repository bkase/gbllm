# D192 readiness (d192_readiness.v1)

Proof that the stateful ROM pipeline (generalized from the fixed arm-B d64/ff128/4blk/slots64 builders) accepts a ternary d192/ff384/6blk/slots192 charset-80 export the moment the real S8 distilled student (bd-3771m) lands. Generated by `cargo run -p gbf-bench --bin d192-readiness`; every number is program output at git `bb215ea09f2b7c389aaf6e6abd19f2c20ef216b2`.

- 973824 MACs/token; one-token mean 20195395 M-cycles; generation-loop mean 20198143 M-cycles = **19.262 s/token** on DMG vs the ~7.1 s/char projection (2.71x)

## Caveats

- The gate model is SYNTHETIC (deterministic seeded weights mirroring the export format and weight statistics), not tonight's real distilled student; the real checkpoint may differ in accumulator ranges. The width decision is structural (worst case over actual weights), so a real checkpoint can only be safer, but its per-row scale magnitudes must still pass the lowering's u32 epilogue bound.
- Per-block residual dumps and the out-projection accumulator dump are dropped at this topology (WRAM budget); the gate still pins the final residual, all block-0 dumps, state vector, in-projection accumulators, y activations, final norm, logits, and argmax byte-exactly.
- Fidelity vs the trainer's f32 forward is meaningless on synthetic weights and is deferred to the real-checkpoint bring-up.
