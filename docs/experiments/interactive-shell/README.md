# Interactive generation shell v0 (interactive_shell_v0.v1)

> **Status: historical V80/charset shell evidence.** The current product uses a
> V1024 byte-BPE tokenizer, UInt16 token feedback, and the compiler-owned
> interactive profile; see [interactive-subword](../interactive-subword/README.md).

A playable demo ROM: boot to an on-screen charset-80 keyboard, type a prompt with the joypad, press START, and watch the stateful LinearState checkpoint generate sampled text into an on-screen transcript — all on-device. This is the **v0 demo shell** scope of bead bd-1kbv1 (not the full M5 cooperative scheduler). Generated by `cargo run -p gbf-bench --bin interactive-shell`; every number below is program output at git `d6c69087542ad14c7cd1b0080d24b64125c49f96`.

## ROM

- 1048576 bytes (39 banks): bank-0 driver 14660 B, UI bank 1859 B (font + polled-joypad keyboard + VBlank BG writer), weight code 461974 B in 34 chunks, tables 35840 B
- Screen: 10x20 transcript (rows 0-9), prompt row 11, message row 12, 4x19 keyboard rows 13-16, help row 17; tile index == charset id, +128 = inverted
- Keyboard: single-page 4x19 grid holding all 76 charset_v1 ids in id order (cell index == charset id == tile index); cursor rendered as the inverted glyph; prompt cap 20 chars (one BG row)
- Controls: D-pad moves the cursor (clamped), A types, B backspaces, START submits

## planv0 InteractionBundle divergences (v0)

- single page instead of the InteractionBundle three-page lowercase/uppercase/symbols keyboard (all 76 ids are directly reachable, so pages are unnecessary at this vocabulary size)
- B is backspace, not the sketched one-shot shift (no shift is needed on a single page)
- no page-cycling key; SELECT is unbound

## UI cadence (the honest numbers)

- Idle input: joypad polled once per frame (59.7 Hz), cursor/typing feedback within one frame
- Warmup: **3.44 s per prompt char** on DMG (3603338 M-cycles mean); the consumed prompt char is highlighted at each boundary
- Generation: **3.40 s per token** on DMG (3569577 M-cycles mean, VBlank alignment included) — one transcript glyph + block cursor per boundary; the screen is otherwise static during the forward pass

## Interrupt policy

- IME stays off for the whole session (di at entry, never ei): V3 weight chunks repurpose SP as the pop-stream pointer, so an ISR mid-kernel would corrupt the weight stream. UI work happens only at token boundaries and in the idle input loop; VBlank is found by polling LY. DeadlineAware yield integration is the planv0 scheduler beads' follow-up.

## Caveats

- v0 demo shell, not the full M5 cooperative scheduler: the screen is static for one full forward pass between token boundaries (~3.40 s of DMG time per token at this checkpoint); the per-token transcript glyph + block cursor and the per-char warmup highlight are the progress affordances.
- The scripted gate runs in the emulator (gbf-emu headless adapter), not on hardware; all timing is DMG M-cycle-accurate emulated time.
- The RNG seed is host-poked for the gate; interactively, the XorShift16 state carries across runs within a session (seed 0 canonicalizes to 1), so an unpoked cart always plays the same first generation for a given prompt.
- Sample quality must be judged honestly: the model is the 4-block d64 S5 arm-B bring-up checkpoint (~3.3 bpc), so text is English-like at best.
