## Quality: the honest verdict

The bead's quality bar is "beats KN-5 on gutenberg_val (bd-do7sq quality bar, tied to the S4/S8 scoring; KN-5 reference = bd-2nca full-corpus fit)" — status: **OPEN**.

| model | bpc/normalized-char | bits/raw-byte |
|---|---|---|
| deployed d192 integer path (state-int-semantics.v2) | 2.9883 | 2.9707 |
| deployed d192 trainer hard-ternary (f32 semantics) | 2.7786 | 2.7622 |
| KN-5, train cap full (489,614,571 train bytes) | 2.2718 | 2.2584 |
| KN-5, train cap 256 MiB | 2.2851 | 2.2717 |
| KN-5, train cap 64 MiB | 2.3402 | 2.3264 |

- The deployed model does **not** beat KN-5: +0.7123 bits/raw-byte vs the full-corpus fit.
- KN-5 does not fit on-cart: the full-corpus fit holds 4621191 unique n-gram entries (orders 2-5; 3759337 unique 5-gram contexts alone) and the 256 MiB-cap fit still holds 2715582 5-gram contexts. Every entry needs a packed multi-char context key plus smoothed continuation statistics — several bytes per entry before any runtime code — while the 8 MiB MBC5 ROM ceiling is already saturated by the deployed d192 ROM (8,388,608 bytes, ~6.07 MiB of it weight code). No committed on-cart KN-5 representation or DMG-latency evaluation of one exists.
- Honest claim of this packet: best deployable model to date that fits the cart and the UX budget; output is coherent English-like pseudo-prose, not KN-5-beating text.
- Named next levers (owner bd-3771m):
  - close the hard-ternary QAT gap (scale run 2 widened it 3.6x: +0.1033 bpc; levers: longer hardness warmup, later hard switch, lower hard-phase lr, gap-aware distill weight schedule)
  - raise ternary sparsity (deployed zero fraction 0.0085; V3 kernels skip zeros, so sparsity buys both quality-per-byte and latency)
  - longer training / better teacher-student recipes on the saved 75k-step teacher (student-only reruns cost ~8.3 h)

## Caveats

- Scripted emulator demo (gbf-emu headless, DMG M-cycle-accurate): the real-hardware flashcart smoke is bd-1qa27 and remains open.
- The v0 shell is not the full M5 cooperative scheduler: the screen is static between token boundaries; the transcript glyph + block cursor are the progress affordances (bd-1kbv1).
- The RNG seed is host-poked (0x5EED) so the run is reproducible; an unpoked cart plays the same first generation for a given prompt (XorShift16 seed canonicalizes 0 -> 1).
- On-device verification is capped by the output ring / 200-cell transcript at ~200 tokens per session; this packet's sequence is entirely on-device and entirely host-verified.
